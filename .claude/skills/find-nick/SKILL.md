# Подбор свободного ника в Telegram

Запрос пользователя: $ARGUMENTS

Ты подбираешь username и **проверяешь каждый вариант настоящей проверкой**, запуская
`nickbot/nickcheck.py`. Статус ника берётся только из вывода скрипта: называй ник
свободным, только если скрипт вернул `"status": "free"`. `likely_free` — это «возможно
свободен»: Telegram его не подтверждал, и он может оказаться зарезервирован (так было с
`kvasik`: на t.me и Fragment пусто, а Telegram отвечает «This username is invalid»).

## Инструмент

```bash
python nickbot/nickcheck.py --json cand1 cand2 cand3 ...
```

Ответ:

```json
{"precise_mode": true,
 "results": [{"username": "crumbly", "status": "free", "reason": "свободен", "precise": true}]}
```

- `status`: `free` — свободен, подтвердил Telegram · `likely_free` — не найден на t.me и
  Fragment, но Telegram не подтверждал · `taken` — занят · `fragment` — продаётся на
  Fragment (бесплатно не занять) · `invalid` — не по формату или запрещён (причина в
  `reason`) · `unknown` — не удалось проверить.
- `precise_mode: true` — проверял сам Telegram, статусы точные. `false` — проверка по
  страницам t.me и Fragment: занятые видны, а свободные подтвердить нельзя, поэтому они
  приходят как `likely_free`, никогда как `free`.
- Код возврата 0 — есть `free` или `likely_free`, 1 — нет (это не ошибка), 2 — ошибка запуска.
- До 50 ников за вызов; результаты кэшируются на 15 минут, повторно проверять не нужно.
- Если `ModuleNotFoundError` — выполни `pip install -r nickbot/requirements.txt`.

## Правила формата username

5–32 символа, только латиница `a–z`, цифры и `_`, начинается с буквы, не заканчивается
на `_`, без `__` подряд. Регистр не важен. Не предлагай варианты, которые нарушают правила.

## Как работать

1. **Пойми запрос**: смысл, настроение, язык, длина, для чего ник (личный, канал, бот —
   у ботов username должен заканчиваться на `bot`). Если запрос пустой — спроси одной
   фразой, какой ник нужен. В остальных случаях не переспрашивай, а решай сам.
2. **Придумай 15–25 кандидатов** — осмысленных и читаемых: игра слов, слияние слов,
   сокращения, ассоциации, слова из других языков (латиницей), звукоподражание.
   Не используй шаблоны: приписанные цифры, `x`, `_official`, `real`, `the`, `its`,
   удвоенные буквы — только если пользователь сам об этом просит.
3. **Проверь** всех одним вызовом `nickcheck.py --json`.
4. **Сделай выводы** из занятых: короткие и словарные слова обычно заняты — уходи в
   составные, редкие, переосмысленные варианты. Повторяй шаги 2–3, пока не наберётся
   5+ свободных хороших ников. Предел — 5 раундов или ~120 проверок.
5. **Ответ**: таблица из 5–10 лучших ников — `@ник`, статус и пояснение в несколько
   слов, сначала `free`, потом `likely_free`. Ниже одной строкой: сколько всего проверено
   и сколько из них занято. Если в таблице есть `likely_free` — прямо назови их
   «возможно свободны, Telegram не подтвердил», посоветуй попробовать по очереди, начиная
   с первого, и предложи точную проверку (`TG_API_ID`/`TG_API_HASH` в `nickbot/.env` и
   `python nickbot/login.py`). Не пиши про `likely_free` «свободен».

Если почти все результаты `unknown`, значит нет доступа к t.me/fragment.com и нет
Telegram-сессии. Скажи об этом и предложи настроить точную проверку
(`TG_API_ID`/`TG_API_HASH` в `nickbot/.env` и `python nickbot/login.py`, см.
`nickbot/README.md`). Не выдавай непроверенные ники за свободные.

Если пользователь прислал готовые ники для проверки, просто прогони их через скрипт и
покажи результат с причинами для `invalid`. Подбирай новые, только если он об этом попросит.
